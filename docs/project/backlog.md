# 백로그

MVP 범위(F01–F13)와 단계 6–7의 F14·F20은 들어갔습니다. 이 표는 **지금 열려 있는 것**만 순위대로 담습니다. 끝난 것은 [roadmap](../product/roadmap.md) 단계 표에 있습니다.

## P0 — 문서가 약속한 것이 코드에 없다

비어 있습니다. 마지막 항목이던 "휴지통 정리에 로그·인맥 추가"는 `RetentionSweeper`가 `career_logs`·`contacts`를 지우면서 닫혔습니다(`fix(worker): sweep career logs and contacts out of the trash`). 새 소프트 삭제 테이블을 만들 때마다 sweeper 순서에 넣는 것이 이 칸을 비워 두는 방법입니다.

## P1 — 다음 단계

| 순위 | 작업           | 산출물                                     | 완료 기준                             | 선행          |
| ---- | -------------- | ------------------------------------------ | ------------------------------------- | ------------- |
| P1   | F15 증언       | `Attestation`, V23, 메일 잡, 공개 응답, 웹 | 증언이 외부 검증 Evidence가 됨        | ADR-0013 머지 |
| P1   | 가져오기 2단계 | 가져온 문서 층(`VersionAuthor.IMPORTED`)   | 과거 제출물이 편집 가능한 출발점이 됨 | 없음          |

[personal-archive-import](../product/personal-archive-import.md)의 **1단계는 들어갔습니다** — 번들 형식, `/imports`, `import.plan`/`apply`, 그리고 `/career/imports` 검토 화면까지. 지원 이력과 공고 원문이 한 번에 들어오고, 공고 일괄 등록 입구도 함께 풀렸습니다. 2단계는 그 위에서 과거 제출 문서를 편집 가능한 버전으로 올립니다. F15는 여전히 ADR-0013이 전제이고, 마이그레이션 번호는 가져오기가 V21·V22를 쓰면서 V23으로 밀렸습니다.

## P2 — 결정이 필요한 것

[career-hub-alignment](../product/career-hub-alignment.md)의 열린 질문에 달려 있습니다. 답이 나오기 전에는 설계만 합니다.

| 작업                    | 선행 결정                                    |
| ----------------------- | -------------------------------------------- |
| 마감 중심 대시보드      | 첫 화면이 축적 현황인가 오늘의 작업 목록인가 |
| 경력기술서 문서 유형    | 없음 (enum 네 곳 + 템플릿, 평범한 작업)      |
| 마감 경과 미제출의 결말 | 상태로 둘 것인가 파생 표시로 충분한가        |
| 지원 건 = 문서 묶음     | 제출 스냅샷이 여러 버전을 묶는가 (ADR 감)    |
| 면접 기록의 자리        | ProofU의 사실인가 iterview의 데이터인가      |
| 가져오기 3·4단계        | 위 "면접 기록의 자리"                        |
