# 0013 트랜잭션 메일: 제공자 중립 발송 경로와 제3자 메일 원칙

- 상태: **제안**
- 일자: 2026-10-15

## 맥락

지금까지 ProofU는 메일을 보내지 않는다. 로그인·이메일 인증·계정 복구 메일은 IdP의 몫이다([ADR-0010](0010-oidc-provider-and-session-model.md) 결정 1 §7). 링크드인 기능 편입 기획([network-and-social-proof.md](../../product/network-and-social-proof.md))의 단계 7–8이 처음으로 **ProofU가 직접 보내는 메일**을 요구한다.

| 메일           | 받는 사람                     | 기능 | 성격                                         |
| -------------- | ----------------------------- | ---- | -------------------------------------------- |
| 증언 요청      | **제3자**(사용자가 적은 인맥) | F15  | 사용자가 건별로 승인한 1통. 자동 재발송 없음 |
| 증언 응답 사본 | 제3자(응답자)                 | F15  | 응답 직후 1통. 철회 링크 포함                |
| 추천 요청      | 제3자                         | F16  | F15와 같은 경로                              |
| 기한 알림 요약 | 사용자 본인                   | F18  | 설정에서 켠 경우만(기본 꺼짐)                |

그래서 이 결정은 "어느 회사의 API를 쓰나"보다 **제3자에게 가는 메일을 어떻게 다루나**가 먼저다.

지켜야 하는 제약:

- **처음 들어오는 제3자 개인정보.** 받는 사람의 이메일 주소와 Claim 원문이 발송 제공자에게 넘어간다. 개인정보 처리 위탁이고, 제공자가 국외에 저장하면 국외 이전 고지 대상이다. 받는 사람은 ProofU 사용자가 아니라 동의한 적이 없다.
- **토큰 링크가 본문에 있다.** 증언 응답 링크는 1회용 토큰이 곧 권한이다(14일 만료, 응답 후 잠금). 링크를 다시 쓰는 기능(클릭 추적)이 있으면 제공자가 토큰을 보고 중계한다.
- **클라우드·리전이 미정**이다([open-decisions](../../project/open-decisions.md)). 특정 클라우드의 메일 서비스를 고르면 그 결정에 기운다.
- **도달률.** Gmail·Yahoo는 발신 도메인 인증(SPF·DKIM)과 DMARC 정렬이 없으면 거부하거나 스팸으로 보낸다. 새 발신 도메인은 평판이 없다.
- **비동기 경로는 이미 있다.** `jobs` 테이블 + 워커([ADR-0004](0004-async-jobs.md)). 기획서는 새 잡 `attestation.notify`를 예약해 두었다.
- **로그에 본문·연락처 금지**, 메트릭 라벨에 workspace id 금지(관측성 규칙).

## 선택지

### 발송 구조

| 구조                                           | 장점                                                                           | 단점                                                                    |
| ---------------------------------------------- | ------------------------------------------------------------------------------ | ----------------------------------------------------------------------- |
| **A. 잡 + 제공자 중립 `MailSender` 포트**      | 재시도·멱등·감사가 기존 잡 체계로, 제공자 교체가 어댑터 하나, 로컬은 SMTP 캐처 | 어댑터와 반송 웹훅 처리를 직접 만든다                                   |
| B. 요청 스레드에서 제공자 SDK 직접 호출        | 가장 단순                                                                      | 제공자 장애가 API 오류가 되고, 재시도·중복 방지가 없다                  |
| C. 제공자의 템플릿·자동화(시퀀스, 캠페인) 사용 | 템플릿 편집기·분석을 공짜로                                                    | 본문과 수신자 목록이 제공자에 저장, 클릭·열람 추적이 기본, 교체 비용 큼 |

| --------------------- | ------------------------------------- | -------------------------- | ----------------------------------------------------------------------------------------------------- |

## 결정 (제안)

**A. 잡 + 제공자 중립 포트**로 만들고, 첫 어댑터는 **Amazon SES(서울 리전)** 로 한다. 대안 어댑터는 **NHN Cloud Email**. 미국에만 저장하는 제공자(Resend, Postmark)는 제3자 연락처의 국외 이전이 생기므로 쓰지 않는다. 클라우드가 AWS가 아니게 되면 SES 대신 NHN Cloud를 재검토하되, 포트와 아래 원칙은 그대로다.

1. **포트.** `MailSender.send(OutboundMail): MailReceipt`를 워커에 둔다. 기능 코드는 제공자 SDK를 직접 쓰지 않는다(AI 게이트웨이와 같은 원칙). 어댑터는 `ses`, `smtp`(로컬 Mailpit 캐처·대체 제공자), `log`(테스트: 본문 없이 메타데이터만)이며 `MAIL_PROVIDER`로 고른다. production 프로필은 `log`로 기동되지 않는다.
2. **잡으로만 보낸다.** 요청 화면은 `attestation.notify`(그리고 같은 모양의 `referral.notify`, `notification.digest`)를 큐에 넣고 202를 돌려준다. 잡은 `(용도, 대상 id)`로 **한 번만** 보낸다 — 재시도가 두 번째 메일이 되지 않도록 발송 기록(`outbound_mails`: 용도, 대상 id, 수신자 해시, 제공자 메시지 id, 상태, 시각)을 먼저 확인한다. 본문과 주소 원문은 이 표에 저장하지 않는다.
3. **추적하지 않는다.** 열람 픽셀·클릭 추적·링크 다시 쓰기를 끈다(SES 구성 세트에서 끄고 어댑터 테스트로 확인). 토큰 링크가 제공자 리다이렉트를 거치지 않게 하기 위해서이고, 받는 사람을 추적할 이유도 없다. 증언 응답률은 우리 쪽 응답 기록으로 잰다.
4. **본문 최소화.** 제3자 메일에는 Claim 원문 한 문장, 사용자가 직접 쓴 요청문, 사용자의 표시 이름, 링크, 수신 거부 링크만 넣는다. 다른 기록·연락처·첨부는 넣지 않는다. 템플릿은 저장소에 코드로 두고(제공자 템플릿 기능 미사용), 한국어·영어 두 벌.
5. **수신 거부의 원천은 우리 DB다.** `mail_suppressions`(수신자 이메일의 **키 있는 해시**, 사유 `UNSUBSCRIBED`/`BOUNCED`/`COMPLAINED`, 시각)를 발송 전에 확인하고, 걸리면 보내지 않고 요청을 실패 사유와 함께 닫는다. 사용자에게는 "받는 사람이 메일을 받지 않도록 설정했습니다"만 알리고 언제·왜는 알리지 않는다. 제공자의 반송·불만 이벤트는 웹훅으로 받아 같은 표에 넣는다. 수신 거부는 계정 삭제와 무관하게 **영구**다(받는 사람의 권리이므로).
6. **발신 도메인 분리.** 서비스 도메인과 분리한 하위 도메인(예: `mail.<도메인>`)에 SPF·DKIM(2048비트)·DMARC(`p=quarantine`부터, 보고서 수신)를 건다. 메일마다 `List-Unsubscribe`와 `List-Unsubscribe-Post`(원클릭)를 붙인다. 회신 주소는 사용자 본인이 아니라 받지 않는 주소로 두고, 본문에 "회신은 전달되지 않습니다"를 적는다 — 사용자의 이메일을 제3자에게 노출하지 않는다.
7. **악용 상한(기획서 미확정 항목의 초기값).** 증언·추천 요청은 워크스페이스당 **월 10건**, 같은 수신자에게는 **7일**에 한 번, 가입 후 **24시간**이 지나야 보낼 수 있다. 상한은 `RetentionPolicy`처럼 domain 값 객체로 검증하고 바꾸면 이 표를 고친다. 반송률·불만률을 메트릭(`proofu_mail_*`, 라벨은 용도·결과만)으로 내고 SES 계정 경고 수준 전에 알림을 건다.
8. **로컬과 테스트.** compose에 `--profile mail`로 Mailpit을 두고 `smtp` 어댑터가 거기로 보낸다. E2E는 Mailpit API로 받은 메일의 링크를 열어 응답까지 간다. 실제 SES 호출은 키가 있을 때만 도는 스모크로 한정한다(AI 라이브 체크와 같은 방식).

## 결과

- 좋은 점: 제공자를 바꿔도 기능 코드와 수신 거부 기록이 남는다. 제3자 연락처가 국외로 나가지 않는다(SES 서울 또는 NHN). 토큰 링크가 제3자 시스템을 거치지 않는다.
- 비용: 반송·불만 웹훅, 발송 기록·수신 거부 표, 템플릿 두 벌, Mailpit 기반 E2E를 직접 만든다. SES 샌드박스 해제 심사가 출시 일정에 들어간다.
- 위험: 신규 발신 도메인의 평판이 없어 초기에 스팸함으로 갈 수 있다(DMARC 보고서로 관찰). 받는 사람이 요청을 스팸으로 신고하면 계정 평판이 떨어진다 — 상한과 24시간 지연이 1차 방어다.
- 법률 확인(일본 리전 검토와 함께 요청): 증언·추천 요청이 정보통신망법상 광고성 정보에 해당하지 않는다는 판단, 처리 위탁 고지에 메일 제공자 추가, 수신 거부 해시를 영구 보관하는 근거.
- 후속 작업(단계 7 착수 시):
  - [ ] 마이그레이션: `outbound_mails`, `mail_suppressions` (계정 삭제 시 `outbound_mails`는 지우고 `mail_suppressions`는 남김 — `docs/data/retention.md`)
  - [ ] 워커 `MailSender` 포트와 `ses`·`smtp`·`log` 어댑터, `JobTypes`에 `attestation.notify`
  - [ ] 공개 엔드포인트: 수신 거부(`/public/mail/unsubscribe/{token}`), 제공자 웹훅(서명 검증)
  - [ ] `application-production.yml`·`docs/operations/deployment.md`에 `MAIL_*` env, `infra/observability/alerts.yml`에 반송·불만률 규칙
  - [ ] `docs/security/privacy-requirements.md`·`threat-model.md`에 제3자 메일 항목

## 재검토 조건

클라우드가 AWS가 아닌 곳으로 정해질 때(NHN Cloud 또는 그 클라우드의 메일 서비스로 어댑터 교체), 월 발송량이 상한 설계를 넘어설 때, 사용자 대상 마케팅 메일이 필요해질 때(별도 스트림·별도 동의로 분리하고 이 경로를 쓰지 않는다), 증언 응답률이 목표(40%)에 못 미치고 원인이 도달률일 때.
