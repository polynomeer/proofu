# 근거화와 환각 방지 정책

## 컨텍스트 구성

1. 사용자가 선택한 지원 건과 문서 목적을 기준으로 허용 범위를 결정합니다.
2. 공고 snapshot과 **승인된** Requirement만 사용합니다.
3. Requirement별 후보 원천 데이터를 검색하고 민감도 및 공개 범위로 필터링합니다.
4. 후보 Claim과 Evidence 요약에 불변 `sourceId`와 `revision`을 붙입니다.
5. 프롬프트에 사실과 지시를 명확히 구분하고 외부 문서의 명령문은 데이터로 취급합니다.
6. 모델 출력은 JSON Schema로 검증하며 참조한 `sourceId`가 입력 집합에 존재하는지 확인합니다.
7. 검증 실패 또는 출처 누락 시 자동 채택하지 않고 재시도 또는 사용자 검토 상태로 전환합니다.

## 환각 방지

- 입력에 없는 회사명, 기간, 기술, 수치, 역할을 새로 생성하지 않습니다.
- 근거의 범위를 넘어 인과 관계를 확대하지 않습니다.
- 모델이 반환한 식별자를 서버가 화이트리스트로 다시 검증합니다.
- `unsupported`와 `inferred` 문장을 사용자 승인 없이 최종 내보내기에 포함하지 않습니다.
- 수치 변환과 기간 계산은 모델 문장이 아니라 결정적 코드로 수행합니다.
- 프롬프트 인젝션 가능성이 있는 공고 원문과 Evidence 파일은 명령이 아닌 인용 데이터 영역으로 격리합니다.
- AI는 Evidence 검증 상태를 올릴 수 없습니다.
