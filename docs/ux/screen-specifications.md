## 공통 상태

| 상태       | 표현                       | 필수 행동                        |
| ---------- | -------------------------- | -------------------------------- |
| Loading    | 스켈레톤 또는 버튼 스피너  | 기존 레이아웃 점프 방지          |
| Empty      | 이유와 첫 행동 설명        | 샘플 데이터를 자동 생성하지 않음 |
| Error      | 문제 원인과 영향 범위      | 재시도 또는 입력 수정            |
| Offline    | 상단 연결 상태와 저장 대기 | 복구 후 동기화                   |
| Permission | 접근 불가 이유             | 소유자 또는 설정으로 이동        |
| Success    | 행동 결과를 짧게 확인      | 연속 작업을 방해하지 않음        |

## 상태 구현 (현재 코드)

| 상태       | 어디서                                                                                                                                        |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| Loading    | 목록 라우트의 `loading.tsx` → `ListSkeleton`(레이아웃 유지, `aria-busy`, `prefers-reduced-motion` 존중). 상세 라우트는 스트리밍하지 않는다    |
| Error      | `(app)/error.tsx` — 무엇이 실패했는지·다시 시도·대시보드로. 예외 메시지는 보여 주지 않고 `digest`만 노출. 셸 자체가 깨지면 `global-error.tsx` |
| Empty      | 화면별 `EmptyState`(다음 행동 하나)                                                                                                           |
| Not found  | 앱 셸 안 `(app)/not-found.tsx`와 리소스별 `not-found.tsx`, 셸 밖 주소는 루트 `not-found.tsx`                                                  |
| Permission | 다른 워크스페이스 리소스는 404로 통일(존재 여부를 흘리지 않는다), 만료 세션은 로그인으로 되돌림                                               |
| Offline    | 미구현 — 저장 대기·동기화 설계 후                                                                                                             |

데이터 조회 실패는 화면이 직접 `ErrorState`로 처리하고(예: 목록), 처리하지 못한 예외만 `error.tsx`로 올라갑니다.

**목록은 조용히 잘리지 않습니다.** 페이지를 넘길 수 있는 목록(커리어·Evidence·공고·문서·기술·역량·경력별 프로젝트)은 "다음"이나 "더 보기"를 제공하고(`LoadMore`, 페이지 크기 `PAGE_LIMIT`), 페이지를 넘길 수 없는 곳(지원 보드, 선택 목록)은 **무엇까지 보여 주는지 문장으로 밝힙니다**(보드는 `truncated`, 선택 목록은 `PICKER_LIMIT`). 새 목록을 만들 때 둘 중 하나를 반드시 고릅니다.

## 접근성과 반응형

- WCAG 2.2 AA를 목표로 하며 키보드만으로 핵심 여정을 완료할 수 있어야 합니다.
- 상태와 신뢰도는 색상만으로 구분하지 않고 텍스트 또는 아이콘 레이블을 함께 제공합니다.
- 폼 오류는 필드와 연결되고 스크린리더가 즉시 읽을 수 있어야 합니다.
- 모바일에서는 데이터 조회와 간단 편집을 지원하고 복잡한 문서 레이아웃 편집은 데스크톱을 우선합니다.
- DOCX와 PDF 출력은 최소 11포인트 본문과 충분한 명암을 유지합니다.
