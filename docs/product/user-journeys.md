# 사용자와 사용자 여정

## 페르소나

| 페르소나         | 상황                                        | 핵심 요구                                    | 주요 위험                             |
| ---------------- | ------------------------------------------- | -------------------------------------------- | ------------------------------------- |
| 경력 개발자      | 여러 프로젝트와 성과가 있으나 문서가 분산됨 | 성과를 재사용 가능한 근거로 관리             | 회사 기밀이 Evidence에 포함될 수 있음 |
| 이직 준비자      | 짧은 기간에 여러 회사에 맞춤 지원           | 공고별 차이를 빠르게 반영                    | AI 문장을 사실로 오인할 수 있음       |
| 장기 경력 관리자 | 당장 지원하지 않아도 기록을 축적            | 시간순 회고와 역량 변화 추적                 | 입력 부담으로 데이터가 오래됨         |
| 기술 직군 사용자 | 수치, 프로젝트 링크, 산출물이 중요          | 구조화된 필드, Evidence 연결, 기술 스택 표현 | —                                     |

## 핵심 여정

1. 사용자는 기존 이력서 또는 직접 입력으로 경력 원천 데이터를 만듭니다.
2. 각 성과와 주장에 URL, 파일, 메모 등 Evidence를 연결하고 공개 범위를 지정합니다.
3. 채용공고를 가져오고 원문 및 출처를 스냅샷으로 저장합니다.
4. 시스템이 필수 조건, 우대 조건, 책임과 기술을 추출하고 사용자가 이를 검토합니다.
5. 시스템이 요구사항마다 관련 경험과 Evidence를 제시하며 부족한 부분을 표시합니다.
6. 사용자는 추천 항목을 선택해 이력서 또는 자기소개서 초안을 생성합니다.
7. 사용자는 근거 표시를 확인하고 문장을 수정·승인한 뒤 버전을 저장합니다.
8. 제출 시 공고, 문서, 원천 데이터를 불변 스냅샷으로 고정합니다.
9. 서류 결과를 기록하고 탈락이면 사실과 가설을 분리해 회고합니다.
10. 서류 합격이면 사용자의 동의를 받아 iterview로 최소 정보를 전달합니다.

## 감정적 목표

사용자는 시스템이 나의 경력을 과장하거나 대신 판단한다고 느끼지 않아야 합니다. 기록이 사라지지 않고, 어떤 문장이 어떤 사실에서 나왔는지 확인할 수 있으며, 최종 결정은 자신이 한다는 통제감을 제공해야 합니다.
