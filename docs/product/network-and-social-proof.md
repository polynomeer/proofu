# 인맥과 제3자 증명 (링크드인 기능 편입 기획)

링크드인의 기능 중 ProofU에 들여올 것과 들이지 않을 것을 판정하고, 들여올 것을 ProofU의 기존 모델로 번역한 기획입니다. 이 문서는 **제안**이며 결정되지 않은 항목은 [project/open-decisions.md](../project/open-decisions.md)에 있습니다. 단계가 승인되면 PRD·로드맵·정보구조·데이터 사전을 함께 고칩니다(§승인 시 함께 바꿀 문서).

## 결론

> 링크드인에서 ProofU가 가져올 가치는 **네트워크가 아니라 제3자 검증**입니다. 인맥은 피드의 대상이 아니라 **Evidence의 출처**로 들어옵니다.

ProofU는 이미 `verification = EXTERNALLY_VERIFIED`를 "연동 전용"으로 비워 두었고([domain/evidence-model.md](../domain/evidence-model.md)), `REFERENCE_LETTER` 유형과 `BEHAVIORAL` 요구사항 범주("제3자 또는 결과 Evidence")도 제3자를 전제합니다. 지금 그 자리를 채울 수 있는 것은 사람뿐입니다 — AI는 검증 상태를 올릴 수 없습니다. 링크드인의 추천글(Recommendation)이 바로 이 구멍에 맞고, ProofU에서는 **증언(Attestation)** 으로 번역됩니다.

반대로 링크드인 가치의 큰 부분(아는 사람 추천, 동문 찾기, 프로필 열람자, 피드의 유통)은 **전역 사용자 그래프나 청중이 있어야 작동**합니다. 사용자 한 명의 워크스페이스에서는 가치가 0이고, 비용은 제3자 개인정보 수집으로 즉시 발생합니다. 그래서 그 묶음은 흉내내지 않고 비목표로 못 박습니다.

다만 그 기능들을 통째로 자르면 안 되는 경우가 있습니다. 한 기능이 **그래프에 기대는 성질과 그렇지 않은 성질을 함께** 가질 때입니다 — 게시물은 유통(버린다)과 기록 습관(가져온다)이고, 2촌 안내는 남의 그래프(버린다)와 내가 적은 인맥의 소속(가져온다)이며, 스킬 보증은 집계 수치(버린다)와 이름 있는 개별 확인(가져온다)입니다. 첫 판정에서 이 셋을 덩어리로 보고 잘라냈고, 재검토로 되돌렸습니다(§재검토 기록).

## 판정 기준

각 기능을 네 가지 질문으로 판정했습니다. 하나라도 어기면 제외합니다. 단, **기능 전체가 아니라 그 기능의 각 성질에** 적용합니다 — 한 기능 안에서 어기는 성질만 버리고 나머지는 번역합니다.

| 기준            | 질문                                                                 | 어기는 예                              |
| --------------- | -------------------------------------------------------------------- | -------------------------------------- |
| 사실성          | 이 기능이 **사실 또는 사실의 출처**를 남기는가, 인기 신호를 남기는가 | 스킬 보증 수, 프로필 열람자            |
| 단독 가치       | 사용자가 **혼자서도** 가치를 얻는가                                  | 아는 사람 추천, 동문 찾기, 피드의 독자 |
| 판단 주체       | 판단을 **사용자가** 하는가, 도구가 대신 하는가                       | 스킬 평가 시험, 상위 지원자 표시       |
| 개인정보 최소화 | 새로 들어오는 개인정보가 기능에 **꼭 필요한 최소**인가               | 연락처 전체 가져오기, 전역 인맥 그래프 |

## 포함 기능

PRD 표와 같은 형식입니다. ID는 예약이며 PRD 반영은 단계 승인 시 합니다.

| ID  | 기능             | 요구사항                                                     | 완료 기준                                                         |
| --- | ---------------- | ------------------------------------------------------------ | ----------------------------------------------------------------- |
| F14 | 인맥 기록        | 함께 일한 사람을 경력·프로젝트에 연결해 비공개로 기록합니다. | 상호 승인 없이 저장되고, 내보내기·계정 삭제에 포함됩니다.         |
| F15 | 증언             | 선택한 Claim을 제3자가 토큰 링크로 확인합니다.               | 확인 응답이 외부 검증 Evidence가 되고 원문·revision이 고정됩니다. |
| F16 | 추천 경로        | 지원 건에 누구를 통해 지원했는지 기록합니다.                 | 회고 비교 맥락에 사실로 제공되고 원인은 추론하지 않습니다.        |
| F17 | 커리어 희망 조건 | 희망 직무·지역·고용형태·시작 가능일을 보관합니다.            | 근무 조건 요구사항에 후보 사실로 제시되고 점수는 바뀌지 않습니다. |
| F18 | 기한 알림        | 자격 만료, 공고 마감, 무응답 증언을 알립니다.                | 앱 내 알림이 쌓이고 메일은 기본 꺼짐입니다.                       |
| F19 | 공유 프로필      | 공개 범위 `PUBLIC` 기록만으로 읽기 전용 페이지를 고정합니다. | 스냅샷이 불변이고 즉시 폐기할 수 있으며 검색 노출이 차단됩니다.   |
| F20 | 커리어 로그      | 그때그때 적은 업무 기록을 성과·Evidence로 승격합니다.        | 로그에서 승격한 성과가 원천 데이터와 구분되지 않습니다.           |

### F14 인맥 기록 (Contact)

링크드인의 인맥을 **상호성 없는 사실**로 축소합니다. 수락·승인·공개 프로필이 없고, 상대는 자신이 기록되었다는 사실을 증언을 요청받기 전까지 알지 못합니다.

| 필드                           | 규칙                                                                   |
| ------------------------------ | ---------------------------------------------------------------------- |
| `displayName`                  | 필수, 120자 이하                                                       |
| `email`                        | 선택. 증언·추천 요청을 보내려면 필요                                   |
| `relation`                     | 필수. `MANAGER`/`PEER`/`REPORT`/`CLIENT`/`PARTNER`/`MENTOR`/`OTHER`    |
| `organization`, `role`         | 선택. 당시 소속과 역할                                                 |
| `careerEntryIds`, `projectIds` | 선택. 어디서 함께 일했는지                                             |
| `note`                         | 선택. 비공개 메모                                                      |
| `sensitivity`                  | 고정 `CONFIDENTIAL` 이상 취급 — **AI 컨텍스트와 로그에 넣지 않습니다** |

- 연락처 일괄 가져오기(주소록·소셜 동기화)는 하지 않습니다. 한 건씩 사용자가 입력합니다.
- `workspace_members`(협업 계정)와 다른 개념입니다. 인맥은 ProofU 사용자가 아니어도 됩니다.
- 제3자 개인정보이므로 소프트 삭제 후 보존 기간이 지나면 지우고, 전체 내보내기와 계정 삭제 대상에 넣습니다.

### F15 증언 (Attestation)

ProofU에서 가장 중요한 추가입니다. **AI가 올릴 수 없는 검증 상태를 사람이 올립니다.**

1. 사용자가 Claim 하나와 인맥 하나를 고르고, 확인받을 **문장 원문**과 사용자가 직접 쓴 요청문을 담아 요청을 만듭니다(요청문 AI 생성 없음).
2. 사용자가 발송을 승인하면 `attestation.notify` 잡이 1회성 토큰 링크를 담은 메일 한 통을 보냅니다. 자동 재발송은 없습니다.
3. 응답자는 로그인 없이 링크로 들어와 이름·관계·소속을 밝히고 **확인 / 부분 확인 / 확인 불가** 중 하나와 본문을 남깁니다. AI는 개입하지 않습니다.
4. 응답은 `attestations`(불변)에 저장됩니다.

| 응답      | Evidence                                               | Claim 연결                     |
| --------- | ------------------------------------------------------ | ------------------------------ |
| 확인      | `type=ATTESTATION`, `verification=EXTERNALLY_VERIFIED` | `SUPPORTS`                     |
| 부분 확인 | `type=ATTESTATION`, `verification=UNVERIFIED`          | `PARTIALLY_SUPPORTS` + `scope` |
| 확인 불가 | 만들지 않습니다                                        | 없음 — 요청 이력에만 남습니다  |

- **요청 시점의 Claim `revision`을 고정**합니다. 이후 사용자가 문장을 바꾸면 UI가 "증언 이후 문장이 바뀜"을 표시하고, 그 증언은 바뀐 문장을 지지하지 않습니다. 증언은 사람에 대한 평판이 아니라 **특정 문장에 대한 확인**입니다.
- 응답을 골라 저장할 수 없습니다. "확인 불가"도 남습니다(공유 프로필·내보내기에는 Evidence만 나가므로 외부로 드러나지는 않습니다).
- 응답자는 자기 응답 사본을 메일로 받고, 링크 만료 전까지 철회할 수 있습니다. 철회는 새 행으로 기록하고 Evidence 연결을 끊습니다.
- 토큰 링크는 기본 14일 만료, 1회 열람 후에도 유효하지만 응답 후에는 잠깁니다.

#### 대상 확장: 기술과 역량 (재검토로 추가)

증언 대상은 Claim뿐 아니라 **Skill과 Capability**도 될 수 있습니다(`attestations.target_type`). 링크드인 스킬 보증을 처음에는 통째로 제외했지만, 집계 수치와 개별 증언은 다른 물건입니다.

| 링크드인 보증            | ProofU 증언                                   |
| ------------------------ | --------------------------------------------- |
| 익명에 가까운 집계(12명) | 이름·관계·소속이 있는 개별 응답               |
| 한 번 누르면 끝          | 확인 대상 정의와 응답 본문을 요구             |
| 숙련도처럼 읽힌다        | 숙련도를 바꾸지 않는다 — 연결 상태만 파생한다 |

- 역량 증언은 `capability_evidence`를 통해 `CapabilityEvidenceStatus`를 `VERIFIED`로 올립니다. 지금 역량에는 외부 검증 경로가 아예 없습니다.
- 기술 증언은 Evidence로 남지만 `proficiency`는 건드리지 않습니다 — 자기평가와 분리라는 규칙 그대로입니다.
- **증언 수를 세어 보여주지 않습니다.** 개수는 인기 신호이고, 화면에는 누가 무엇을 확인했는지만 나옵니다.

#### 보류: 되묻기 (도입 트리거 있음)

응답자가 "어느 프로젝트를 말하는지" 되물을 길이 없으면 응답률이 막힙니다. 메시징 기능을 만들지는 않고, **그 요청 1건에 한정한 1회 왕복**(응답자 질문 → 사용자에게 알림 → 사용자 1회 답변 → 응답 가능)만 둡니다. 토큰이 범위를 묶으므로 스팸 면적은 늘지 않습니다.

도입 트리거: 증언 응답률이 목표(40%)에 미달하고, 무응답 요청의 원인 조사에서 "무엇을 확인해야 할지 모르겠다"가 가장 많을 때. 그 전에는 요청문 작성 안내만 개선합니다.

### F16 추천 경로 (Referral)

지원 건에 "누구를 통해, 언제" 지원했는지 기록합니다(`application_referrals`). 내부 추천·지인 소개·공개 지원을 구분합니다.

- `GET /applications/{id}/review-context`에 **사실로만** 추가합니다. 추천 유무를 결과의 원인으로 서술하지 않습니다 — 원인 단정 금지 규칙은 그대로입니다.
- 추천 요청 메일은 F15와 같은 1회성·사용자 승인 경로를 씁니다.

**이 회사에 아는 사람 (재검토로 추가).** 링크드인의 2촌 안내("이 회사에 3명을 알고 있습니다")에서 전역 그래프가 필요 없는 조각만 가져옵니다. 공고의 `company`와 내가 적은 인맥의 `organization`을 대조해 지원 화면에 조용히 표시합니다.

- 내 워크스페이스 데이터만 씁니다. 다른 사용자의 인맥, 회사 직원 목록, 외부 조회는 쓰지 않습니다.
- 조직 사전 없이 **정규화 문자열 대조**(소문자·공백·법인 접미사 제거)로 시작하고, 오탐이 잦으면 보류 중인 조직 사전을 만듭니다.
- 대조 결과는 추천 여부를 권하지 않고 사실만 보여 줍니다. 요청은 사용자가 F15·F16 경로로 직접 보냅니다.
- 과거 소속이 현재 소속과 다를 수 있으므로 인맥에 적힌 시점을 함께 표시합니다.

### F17 커리어 희망 조건 (Career Preferences)

희망 직무, 근무 지역·원격 가능 여부, 고용 형태, 시작 가능일, 구직 상태를 워크스페이스에 1건 보관합니다.

- `RequirementAssessor`가 근무 조건류 `REQUIRED` 요구사항을 판정할 때 **후보 사실**로 제시합니다. 지금은 후보가 없어 전부 `UNMET`입니다.
- **`MatchFeatures`와 `MatchScore`에는 넣지 않습니다.** 점수 항목을 바꾸면 평가 세트를 다시 돌려야 합니다.
- 희망 보상 범위는 선택이며 저장해도 공유 프로필·AI 컨텍스트·내보내기 머리글에 넣지 않습니다.
- 판정은 "사용자 조건과 공고 조건이 일치/불일치"라는 사실 표시이며 합격 판정이 아닙니다.

### F18 기한 알림

`notifications` 테이블 + 앱 내 알림 센터. 메일 다이제스트는 설정이며 기본 꺼짐입니다.

| 알림             | 조건                                                 |
| ---------------- | ---------------------------------------------------- |
| 자격 만료 예고   | `CERTIFICATE` Evidence의 만료일 30·7일 전            |
| 공고 마감        | `job_postings.closes_at` 3·1일 전 (사용자 수동 입력) |
| 증언 무응답      | 요청 후 7일, 만료 2일 전                             |
| 공유 프로필 만료 | 만료 7일 전                                          |
| 근거 완성도      | 근거 없는 주장이 있는 지원 문서를 제출 전에 표시     |

워커의 `RetentionSweeper`와 같은 주기 작업으로 돌리며 `jobs` 테이블을 쓰지 않습니다.

### F19 공유 프로필

링크드인 프로필의 대체가 아니라 **근거까지 보이는 읽기 전용 스냅샷**입니다.

- `visibility = PUBLIC` 원천 기록만 담습니다. `SELECTIVE`·`PRIVATE`은 들어가지 않습니다.
- 민감도 `CONFIDENTIAL`·`RESTRICTED` Evidence는 절대 포함하지 않고, Evidence는 URL과 증언 요약만 노출합니다(파일 다운로드 없음).
- **AI가 생성한 문장은 공유 프로필에 들어가지 않습니다.** 공개되는 것은 사실이고, 생성 문장은 지원 문서 안에서만 존재합니다.
- 발행하면 `shared_profile_snapshots`(불변)로 고정되어, 링크를 받은 사람이 본 내용을 재현할 수 있습니다. 원천이 바뀌면 다시 발행해야 반영됩니다.
- 슬러그는 추측 불가 난수(열거 방지), `noindex` 기본, 만료일 설정 가능, 즉시 폐기 가능. 폐기 후 링크는 410으로 답합니다.
- 연락처 노출은 프로필 규칙을 따라 항목별 선택이며 기본은 전부 꺼짐입니다.

### F20 커리어 로그 (재검토로 추가)

링크드인 게시물에서 **유통은 버리고 습관만** 가져옵니다. 청중도, 반응도, 팔로워도 없는 비공개 업무 기록입니다.

처음에 피드를 "콘텐츠 유통은 제품이 아니다"로 잘라냈지만, 그 판정은 게시물의 두 성질을 한 덩어리로 봤습니다. ProofU의 1순위 리스크는 "경력 입력 부담으로 활성화 저하"([project/risks.md](../project/risks.md))이고, 지원할 때 한꺼번에 성과를 떠올리는 것이 바로 그 부담입니다. 사람들이 링크드인에 수시로 적는 이유는 독자가 있어서이기도 하지만, **그 순간에 적기 때문에 적을 수 있어서**입니다. 후자는 ProofU에 그대로 필요합니다.

| 필드          | 규칙                                                                    |
| ------------- | ----------------------------------------------------------------------- |
| `occurredAt`  | 필수. 기본값 오늘                                                       |
| `body`        | 필수. 짧은 서술 한두 문장                                               |
| `linkIds`     | 선택. 경력·프로젝트 연결                                                |
| `sensitivity` | 필수. **기본 `CONFIDENTIAL`** — 업무 일지에는 회사 정보가 쉽게 들어온다 |
| `promotedTo`  | 선택. 성과 또는 Evidence로 승격한 뒤 가리키는 대상                      |

- 승격은 **복사**입니다. 로그에서 만든 성과는 저장된 뒤 손으로 넣은 성과와 구분되지 않습니다(F13 이력서 가져오기와 같은 선).
- 1단계에는 AI가 없습니다. 사용자가 로그를 골라 성과 폼으로 보냅니다. 로그 묶음에서 성과 후보를 뽑는 것은 F13과 같은 패턴으로 나중에 검토합니다.
- 기본 민감도가 `CONFIDENTIAL`이므로 **AI 동의가 없는 워크스페이스에서는 AI 컨텍스트에 들어가지 않습니다**(`Sensitivity.allowedInAiContext`).
- 반응·공유·공개 범위가 없습니다. 공유 프로필(F19)에도 들어가지 않습니다.

스키마 결정 (V19, 2026-10-15):

- 경력·프로젝트 연결은 `claim_sources`의 다형 참조(`source_type`, `source_id`) 대신 **nullable 외래 키 둘**(`career_entry_id`, `project_id`, 정확히 하나)로 둡니다. 데이터베이스가 직접 막을 수 있고, 백업·복구에 새 비-FK 참조 검사를 더하지 않아도 됩니다.
- 로그는 다른 원천 데이터의 영구 삭제를 **막지 않습니다**: 연결은 `ON DELETE CASCADE`, 승격 포인터는 `ON DELETE SET NULL`이고 `promoted_at`은 남습니다.
- **전역 검색에는 넣지 않습니다.** 기본 민감도가 `CONFIDENTIAL`이고 양이 가장 많이 늘어날 테이블이므로, 로그는 로그 화면에서만 찾습니다(V16식 trigram 인덱스를 더하지 않습니다).

## 지키는 불변식

새 기능이 깨뜨리면 안 되는 기존 규칙입니다. 설계 검토의 체크리스트로 씁니다.

| 불변식                                   | 새 기능에서의 의미                                                         |
| ---------------------------------------- | -------------------------------------------------------------------------- |
| AI는 검증 상태를 올릴 수 없다            | 증언만이 `EXTERNALLY_VERIFIED`를 만든다. 증언 본문은 AI가 쓰지 않는다      |
| `proficiency`는 자기평가다               | 증언 수·보증 수는 숙련도와 역량 수준을 바꾸지 않는다                       |
| 매칭 점수 항목은 고정                    | 희망 조건·증언·추천 경로는 `MatchScore`에 들어가지 않는다                  |
| 불변 테이블은 UPDATE/DELETE 하지 않는다  | `attestations`, `shared_profile_snapshots`가 목록에 추가된다. 정정은 새 행 |
| 개인 연락처는 AI 컨텍스트·로그 금지      | 인맥·증언 응답자 정보도 같은 선을 적용한다                                 |
| 사용자 승인 없는 외부 전송 금지          | 메일은 사용자가 건별로 승인한 1회성 발송만                                 |
| 원인 단정 금지                           | 추천 경로는 결과의 원인으로 서술하지 않는다                                |
| 점수를 합격 확률로 표현 금지             | 근거 완성도는 점수가 아니라 항목별 사실 목록                               |
| 기밀 데이터는 동의 없이 AI 컨텍스트 금지 | 커리어 로그는 기본 `CONFIDENTIAL`이므로 동의 없으면 모델에 가지 않는다     |
| 집계 수치를 역량 신호로 쓰지 않는다      | 증언은 누가 무엇을 확인했는지만 보여 주고 개수를 세지 않는다               |

## 데이터 모델 영향

마이그레이션은 `V19`부터 추가만 합니다(기존 파일 수정 금지).

| 테이블                            | 성격     | 비고                                                                             |
| --------------------------------- | -------- | -------------------------------------------------------------------------------- |
| `contacts`                        | 가변     | `revision`, soft delete. 제3자 개인정보                                          |
| `contact_links`                   | 가변     | 인맥 ↔ 경력/프로젝트 다대다, 집합 교체                                           |
| `attestation_requests`            | 가변     | 상태 `PENDING`/`RESPONDED`/`EXPIRED`/`REVOKED`, 토큰 해시만 저장                 |
| `attestations`                    | **불변** | 응답 본문, 응답자 자기 신고 정보, 대상 revision 고정. 대상은 다형(`target_type`) |
| `application_referrals`           | 가변     | 지원 건당 0..1                                                                   |
| `career_preferences`              | 가변     | 워크스페이스당 1건                                                               |
| `notifications`                   | 가변     | 읽음 처리만 갱신                                                                 |
| `shared_profiles`                 | 가변     | 슬러그, 만료, 폐기                                                               |
| `shared_profile_snapshots`        | **불변** | 발행 시점 내용 전체                                                              |
| `career_logs`, `career_log_links` | 가변     | **V19 반영됨.** `revision`, soft delete, 기본 민감도 `CONFIDENTIAL`              |

enum은 네 곳(domain Kotlin ↔ `migrations/` CHECK ↔ `openapi.yaml` ↔ `docs/domain`)을 함께 바꾸고, 새 enum 컬럼은 `scripts/check-enums.py`의 `COLUMN_ENUM`에 등록해야 CI를 통과합니다.

| enum                 | 변경                                                                                                                                                      |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `EvidenceType`       | `ATTESTATION` 추가. 위치 규칙은 `NOTE`처럼 `body` 필수                                                                                                    |
| `EvidenceSource`     | `THIRD_PARTY` 추가                                                                                                                                        |
| `VerificationStatus` | 변경 없음 — `EXTERNALLY_VERIFIED`가 비로소 쓰인다                                                                                                         |
| 신규                 | `ContactRelation`, `AttestationResponse`, `AttestationTarget`(`CLAIM`/`SKILL`/`CAPABILITY`), `ReferralChannel`, `NotificationType`, `SharedProfileStatus` |

그 외 함께 고칠 곳:

- `AccountExportJobHandler.TABLES`와 `AccountPurgeJobHandler` 삭제 순서에 새 테이블 전부 추가.
- `attestations.target_id`는 `provenance_links.source_id`와 같은 **외래 키 없는 다형 참조**입니다. `scripts/restore.sh --rehearse`의 비-FK 참조 검사와 [operations/backup-recovery.md](../operations/backup-recovery.md)를 함께 고쳐야 합니다.
- `RetentionSweeper` 순서에 `career_log_links` → `career_logs`(아무것도 로그를 참조하지 않으므로 보류 조건 없음) → `contacts` → `contact_links`를 넣고, 만료된 `attestation_requests`·폐기된 `shared_profiles`를 정리 대상에 추가. `attestations`는 불변이므로 계정 삭제 때만 지웁니다.
- 새 목록 화면마다 `(workspace_id, 정렬 시각 DESC, id DESC) WHERE deleted_at IS NULL` 부분 인덱스 (`ListQueryPlanTest`).
- 전역 검색 대상에 인맥 이름을 넣으면 V16과 같은 trigram 인덱스도 함께 추가.

## API·잡·화면

- 새 잡 타입: `attestation.notify`(메일 1통), `profile.publish`(스냅샷 고정). `JobTypes`와 워커 핸들러 상수를 같이 바꿉니다.
- 공개 엔드포인트가 둘 생깁니다 — 증언 응답(`/public/attestations/{token}`)과 공유 프로필(`/public/profiles/{slug}`). 워크스페이스 컨텍스트가 없는 첫 경로이므로 `SecurityConfig`에 명시적 예외와 자체 레이트 리밋이 필요합니다.
- 정보구조에 **1차 메뉴를 추가하지 않습니다**(모바일 하단 바 4칸과 접근성 검사 목록 비용). 배치는 인맥 `/career/contacts`, 커리어 로그 `/career/logs`, 증언 `/evidence/attestations`, 추천 경로는 지원 상세 안, 희망 조건·공유 프로필·알림 설정은 `/settings`입니다.
- 새 화면은 `apps/e2e/tests/accessibility.spec.ts` 목록에 넣습니다(위반 0 유지).
- 공개 화면은 앱 셸 밖이므로 CSP·보안 헤더를 별도로 확인합니다.

새 기능은 ProofU에 **처음으로 제3자 개인정보**를 들여옵니다. 지금까지는 사용자 자신의 데이터만 있었습니다.

| 위험                       | 통제                                                                                                                |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| 제3자 정보 무단 축적       | 한 건씩 입력, 일괄 가져오기 없음, 보존 기간 적용, 내보내기·계정 삭제 포함                                           |
| 증언 요청 스팸             | 워크스페이스 월 요청 상한, 같은 수신자 재요청 7일 간격, 수신 거부 목록(해시) 영구                                   |

| 응답자 신원 사칭           | 응답자 정보는 **자기 신고**임을 Evidence와 문서에 그대로 표시한다                                                   |
| 업무 일지에 회사 기밀 축적 | 커리어 로그 기본 민감도 `CONFIDENTIAL`, AI 컨텍스트 기본 제외, 공유 프로필·내보내기 머리글 미포함, 작성 화면에 안내 |
| 메일 발송 인프라 침해      | 발송 제공자는 미확정(§미확정). 본문에 Claim 원문 외 개인정보를 넣지 않는다                                          |

## 단계 계획

[product/roadmap.md](roadmap.md)의 단계 5(베타) 이후입니다. MVP 범위를 넓히지 않습니다.

| 단계                   | 기간 예시 | 내용                                             | 종료 조건                                                    |
| ---------------------- | --------- | ------------------------------------------------ | ------------------------------------------------------------ |
| 6 커리어 로그 (승인)   | 2주       | F20                                              | 로그에서 승격한 성과가 원천 데이터와 구분되지 않는다         |
| 7 사람이 확인하는 근거 | 4주       | F14 인맥, F15 증언(기술·역량 포함)               | 증언 응답이 외부 검증 Evidence가 되고 제출 문서에서 추적된다 |
| 8 지원 과정의 사실     | 3주       | F16 추천 경로·회사 대조, F17 희망 조건, F18 알림 | 근무 조건 요구사항이 사실 후보로 판정되고 기한 알림이 쌓인다 |
| 9 공유                 | 3주       | F19 공유 프로필                                  | 발행본이 불변으로 재현되고 즉시 폐기된다                     |
| 보류                   | —         | 조직 사전, 공유 링크 열람 수, 증언 되묻기        | 트리거 충족 또는 단계 6–9 사용 데이터 확인 후                |

재검토로 순서가 바뀌었습니다. **단계 6(커리어 로그)이 먼저입니다** — 제3자 개인정보를 전혀 들이지 않으면서 1순위 리스크(입력 부담)를 건드리고, 선행 조건이 없으며, 쌓인 로그가 단계 7에서 증언을 요청할 주장을 만들어 줍니다.

단계 7이 가장 가치가 높고 가장 위험합니다(제3자 개인정보 도입). 단계 7의 개인정보·악용 통제가 검증되기 전에는 단계 8·9를 시작하지 않습니다.

## 재검토 기록

2026-10-15, 첫 판정의 제외 항목을 역진술로 다시 검토했습니다. 세 건은 판정이 틀렸습니다 — 모두 **링크드인 기능의 두 성질을 한 덩어리로 보고** 잘라낸 경우였습니다.

| 기능        | 전   | 후       | 무엇을 잘못 봤나                                                                                          |
| ----------- | ---- | -------- | --------------------------------------------------------------------------------------------------------- |
| 스킬 보증   | 제외 | **일부** | 집계 수치와 이름 있는 개별 확인을 같이 묶었다. 후자는 Evidence이고, 역량에는 외부 검증 경로가 아예 없었다 |
| 피드·게시물 | 제외 | **번역** | 유통과 기록 습관을 같이 묶었다. 습관은 1순위 리스크(입력 부담)를 직접 줄인다                              |
| 2촌 안내    | 제외 | **번역** | 전역 그래프가 필요한 부분과 내 데이터로 답하는 부분을 같이 묶었다                                         |
| 메시징      | 제외 | **보류** | 채널은 필요 없지만 되묻기가 막히면 증언 응답률이 막힌다. 측정 가능한 도입 트리거를 달았다                 |

네 건은 제외를 유지하되 **이미 덮고 있는 경로를 적지 않은 것**이 문제였습니다: 스킬 평가 시험(외부 평가 결과는 이미 `CERTIFICATE`·`METRIC` Evidence), 간편 지원(재사용은 F08·F10), 그룹·이벤트(참가 사실은 Learning 기록), 연봉 추정(희망 조건과 공고 조건의 사실 대조까지는 허용).

바뀌지 않은 제외: 아는 사람 추천·동문 찾기·프로필 열람자(전역 그래프), 보증 수 집계와 숙련도 반영, ProofU가 내는 평가 시험, 자동 제출, 합격 확률·상위 지원자, 채용담당자 기능, 서비스 마켓플레이스.
