# PRD 핵심 기능

| ID  | 기능          | 요구사항                                                   | 완료 기준                                      |
| --- | ------------- | ---------------------------------------------------------- | ---------------------------------------------- |
| F01 | 커리어 데이터 | 경력, 프로젝트, 성과, 기술, 학습 등을 구조화해 관리합니다. | CRUD와 검색, 변경 이력, 내보내기가 동작합니다. |
| F02 | Evidence      | 주장 또는 성과를 파일, 링크, 메모와 연결합니다.            | 근거 상태와 공개 범위를 확인할 수 있습니다.    |
| F03 | 공고 가져오기 | career-ops 또는 수동 입력으로 공고를 저장합니다.           | 원문과 출처, 시각, 해시를 보존합니다.          |
| F04 | 요구사항 분석 | 필수·우대·책임·기술 키워드를 구조화합니다.                 | 사용자가 추출 결과를 수정·승인할 수 있습니다.  |
| F05 | 적합도 분석   | 요구사항별 관련 Evidence와 격차를 제시합니다.              | 각 결과에 이유와 신뢰도를 표시합니다.          |
| F06 | 문서 생성     | 대상 공고에 맞는 이력서와 자기소개서 초안을 생성합니다.    | 모든 핵심 문장이 원천 항목을 참조합니다.       |
| F07 | 편집과 승인   | 사용자가 문장을 편집하고 승인 또는 제외합니다.             | 승인되지 않은 AI 문장을 구분합니다.            |
| F08 | 버전 관리     | 문서 버전 생성, 비교, 복원을 지원합니다.                   | 제출 버전은 불변 스냅샷으로 고정됩니다.        |
| F09 | 내보내기      | DOCX, PDF, Markdown, JSON으로 내보냅니다.                  | 한글 출력과 ATS 텍스트 추출이 검증됩니다.      |
| F10 | 지원 관리     | 관심, 준비, 제출, 서류 결과 상태를 관리합니다.             | 상태 변경 시각과 관련 문서를 보존합니다.       |
| F11 | 서류 회고     | 사실, 가설, 근거, 신뢰도, 개선 행동을 기록합니다.          | 확정 사실과 추정 원인을 분리합니다.            |
| F12 | 면접 인계     | 서류 합격 지원 건을 iterview로 전달합니다.                 | 최소 데이터 계약과 사용자 동의가 적용됩니다.   |

## 성공 지표

| 지표            | 정의                                             | MVP 목표  | 가드레일                       |
| --------------- | ------------------------------------------------ | --------- | ------------------------------ |
| 활성화율        | 가입 후 7일 내 핵심 경력 3건과 Evidence 1건 등록 | 40% 이상  | 과도한 온보딩 강제 금지        |
| 문서 생성 시간  | 공고 저장부터 첫 DOCX 생성까지 중앙값            | 20분 이하 | 사실 검토 시간은 제외하지 않음 |
| 근거 연결률     | 최종 문서 핵심 주장 중 Evidence 연결 비율        | 90% 이상  | 근거 없는 수치 0건             |
| 추천 채택률     | 추천된 경력 문장 중 최종본 채택 비율             | 30% 이상  | 무비판 자동 채택 방지          |
| 재사용률        | 두 번째 지원에서 기존 원천 항목 재사용 비율      | 60% 이상  | 중복 복제율 모니터링           |
| 내보내기 성공률 | DOCX/PDF 생성 성공 비율                          | 99% 이상  | 한글 깨짐과 빈 파일 0건        |
| 회고 완료율     | 서류 탈락 기록 중 회고가 작성된 비율             | 50% 이상  | 원인 단정 표현 경고            |

## 사용자 스토리와 인수 조건

| ID   | 사용자 스토리                                       | 인수 조건                                                              |
| ---- | --------------------------------------------------- | ---------------------------------------------------------------------- |
| US01 | 과거 경험을 한곳에서 관리하고 싶습니다.             | 항목을 생성·수정·보관·삭제할 수 있고 변경 이력이 남습니다.             |
| US02 | 성과가 실제 사실임을 증명하고 싶습니다.             | 주장마다 Evidence를 연결하고 검증 상태를 표시합니다.                   |
| US03 | 공고가 요구하는 내용을 빠르게 이해하고 싶습니다.    | 추출 결과를 필수·우대·책임·기술로 구분하고 편집할 수 있습니다.         |
| US04 | 왜 경험이 추천되었는지 알고 싶습니다.               | 요구사항–Evidence 매칭 이유와 신뢰도가 표시됩니다.                     |
| US05 | 근거 없는 문장이 지원서에 들어가지 않기를 원합니다. | 근거가 없거나 추론인 문장은 경고되고 승인 전 최종 출력에서 제외됩니다. |
| US06 | 제출 당시 문서를 다시 보고 싶습니다.                | 제출 스냅샷이 원천 변경과 무관하게 동일하게 열립니다.                  |
| US07 | 탈락을 다음 지원의 개선으로 연결하고 싶습니다.      | 사실, 가설, 신뢰도, 개선 행동을 각각 기록할 수 있습니다.               |
