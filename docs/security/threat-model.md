# 위협 모델

## 데이터 분류

| 등급 | 코드           | 예시                                 | 처리 기준                                        |
| ---- | -------------- | ------------------------------------ | ------------------------------------------------ |
| 공개 | `PUBLIC`       | 공개 포트폴리오, 공개 저장소         | 사용자가 공개를 명시한 범위에서 사용             |
| 내부 | `INTERNAL`     | 일반 경력 메모, 공고 분석            | 인증된 사용자와 승인된 처리자만 접근             |
| 기밀 | `CONFIDENTIAL` | 회사 내부 성과, 비공개 프로젝트 문서 | 생성 전 별도 경고, 외부 전송 제한                |
| 제한 | `RESTRICTED`   | 신분증, 건강 정보, 계정 비밀         | 원칙적으로 수집 금지, 필요한 경우 별도 법적 검토 |

## 위협과 통제

| 위협             | 영향                           | 주요 통제                                      |
| ---------------- | ------------------------------ | ---------------------------------------------- |
| 교차 사용자 접근 | 다른 사용자의 경력과 문서 노출 | workspace 조건 강제, 객체 수준 권한 테스트     |
| 파일 악성 콘텐츠 | 파서 취약점, 악성 코드         | 유형 검증, 크기 제한, 격리 스캔, 안전한 렌더러 |
| 프롬프트 인젝션  | 데이터 유출, 정책 우회         | 데이터·명령 분리, 허용 원천 제한, 출력 검증    |
| 과도한 로그      | 개인정보와 회사 기밀 노출      | 필드 마스킹, 본문 미기록, 접근 제한, 만료      |
| 링크 탈취        | 내보내기 파일 무단 접근        | 짧은 만료 서명 URL, 재인증, 감사               |
| 공급망 공격      | 빌드 또는 런타임 변조          | 잠금 파일, SBOM, 서명, 취약점 검사             |
| 모델 제공자 오용 | 학습 또는 장기 보존            | 계약과 설정 검토, 최소 전송, 제공자별 정책     |
| 계정 탈취        | 전체 커리어 데이터 노출        | OIDC MFA 지원, 세션 회수, 이상 탐지            |

## 인증과 권한

- 표준 OIDC를 사용하고 비밀번호를 직접 저장하지 않는 구성을 우선합니다.
- 민감 작업(전체 내보내기, 계정 삭제, 연동 변경)에는 최근 재인증을 요구합니다.
- 서버는 모든 리소스 요청에서 workspace 소유권을 검증하며 클라이언트 전달 ID를 신뢰하지 않습니다.
- 운영자 접근은 시간 제한, 승인, 목적 기록, 감사 로그를 적용하고 원문 열람을 최소화합니다.
- 서비스 계정과 워커는 작업에 필요한 최소 권한만 가집니다.
