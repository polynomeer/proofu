# 테스트 전략

## 피라미드

| 수준 | 대상 | 실행 시점 | 도구 |
|---|---|---|---|
| 정적 검사 | 타입, 린트, 보안 규칙, 스키마 | 모든 커밋 | tsc, eslint, ktlint, detekt |
| 단위 | 도메인 불변식, 점수 계산, 변환 | 모든 커밋 | Kotest/JUnit, Vitest |
| 통합 | DB, 객체 저장소, 큐, AI 어댑터 | PR과 main | Testcontainers |
| 계약 | OpenAPI, career-ops, iterview, 이벤트 | PR과 배포 전 | openapi-diff, 계약 fixture |
| E2E | 핵심 사용자 여정과 브라우저 | main과 릴리스 | Playwright |
| AI 평가 | 사실성, 근거, 관련성, 안전성 | 프롬프트·모델 변경 | `packages/ai-evaluation` |
| 성능·보안 | 부하, 권한, 파일 입력 공격 | 릴리스 후보와 정기 | k6, 권한 테스트 |

## 도메인 불변식 테스트 (필수)

- 다른 workspace의 Evidence를 Claim에 연결할 수 없습니다.
- 승인 전 Requirement는 최종 매칭 기준으로 사용할 수 없습니다.
- 지원 상태는 정의된 전이만 허용합니다.
- Submission Snapshot은 갱신과 삭제 대신 정책에 따른 별도 삭제 이벤트만 허용합니다.
- Document Version의 provenance source revision은 생성 후 변경되지 않습니다.
- 민감도 기밀 또는 제한 데이터는 허용되지 않은 AI 컨텍스트에 포함되지 않습니다.

## 테스트 데이터 정책

- 프로덕션 개인정보를 개발 또는 테스트 환경으로 복사하지 않습니다.
- 합성 경력, 공고, Evidence 파일을 `fixtures/`로 관리하고 사실성 평가 정답을 버전 관리합니다.
- 외부 연동은 샌드박스와 계약 fixture를 사용하며 네트워크 실패와 지연을 주입합니다.
- 시간과 무작위 식별자는 주입 가능하게 만들어 테스트를 재현합니다 (`Clock`, `IdGenerator`).
