# 지원 문서 생성과 내보내기

## 콘텐츠 모델

| 문서       | 코드           | 기본 섹션                                   | 규칙                                   |
| ---------- | -------------- | ------------------------------------------- | -------------------------------------- |
| 이력서     | `RESUME`       | 요약, 핵심 역량, 경력, 프로젝트, 기술, 학력 | 1~2페이지 권고, 사실 중심, 중복 최소화 |
| 자기소개서 | `COVER_LETTER` | 지원 동기, 관련 경험, 기여 계획             | 공고 요구와 Evidence를 직접 연결       |
| 포트폴리오 | `PORTFOLIO`    | 소개, 사례(문제·행동·결과), 증빙 링크       | 기밀 제거와 공개 범위 적용             |

## 템플릿 규칙

- 콘텐츠와 표현 형식을 분리하며 템플릿은 데이터를 변경하지 않습니다.
- 섹션은 안정된 `blockId`를 가져 버전 비교와 provenance 연결을 유지합니다.
- 한국어(`ko-v1`)와 영어(`en-v1`) 템플릿은 섹션 id를 공유하고 제목·안내만 다릅니다. 문서의 `language`(`ko`|`en`)가 템플릿을 고르며 초안·내보내기·ATS 검사가 같은 템플릿을 씁니다. 문장 길이와 날짜 표기 규칙은 별도로 둡니다.
- 사용자 정의 템플릿은 허용된 필드와 반복 구문만 사용하고 임의 코드 실행을 금지합니다.
- 문서 생성기 버전과 템플릿 버전을 내보내기 메타데이터에 기록합니다.

## DOCX와 PDF 품질 기준

- 한글 글리프가 누락되지 않고 표 또는 긴 URL이 페이지 밖으로 넘치지 않아야 합니다.
- 제목 계층과 읽기 순서를 유지하며 장식용 텍스트 상자를 최소화합니다.
- PDF 텍스트를 추출했을 때 주요 정보가 논리적 순서로 유지되어야 합니다.
- 문서에는 숨은 프롬프트, 내부 ID, 검토 코멘트가 포함되지 않아야 합니다.
- 생성된 파일의 SHA-256 해시, 크기, 페이지 수, MIME 유형을 기록합니다.
- 본문 최소 11pt.

## ATS 호환성

| 항목     | 기준                                                    |
| -------- | ------------------------------------------------------- |
| 레이아웃 | 단일 열 기본 템플릿, 복잡한 도형과 다단 회피            |
| 텍스트   | 핵심 내용은 이미지가 아닌 실제 텍스트                   |
| 제목     | 경력, 기술, 학력 등 일반적인 섹션 이름                  |
| 날짜     | 일관된 형식과 명확한 시작·종료 기간                     |
| 링크     | 표시 텍스트와 실제 URL 모두 유지                        |
| 검증     | DOCX/PDF에서 텍스트를 다시 추출해 필수 필드와 순서 검사 |

## ATS 검사

`AtsChecker.check`(domain)가 문서 버전을 결정적으로 검사해 항목별 `PASS | INFO | WARN`만 돌려줍니다. 합격 가능성 점수는 없습니다.

| 코드                | 검사                                                                  | 결과                                 |
| ------------------- | --------------------------------------------------------------------- | ------------------------------------ |
| `SECTION_STRUCTURE` | 템플릿 섹션(경력, 기술, 학력 등 일반 이름) 중 내보낼 문장이 없는 섹션 | 없으면 PASS, 있으면 WARN + 섹션 이름 |
| `KEYWORDS`          | 승인된 요구사항 토큰의 절반 이상이 문서에 없는 요구사항               | 없으면 PASS, 있으면 WARN + 요구사항  |
| `CONTACT`           | 이메일·전화번호 패턴                                                  | 둘 다 있으면 PASS, 아니면 WARN       |
| `DATE_FORMAT`       | 날짜 표기(`2024.03`, `2024-03`, `2024년 3월`)가 섞임                  | 한 가지면 PASS, 섞이면 INFO          |
| `LAYOUT`            | 렌더러가 단일 열·표/이미지 없음을 보장                                | 항상 PASS (근거 명시)                |
| `FILE_FORMAT`       | READY 내보내기 중 DOCX/PDF 유무                                       | 있으면 PASS, 없으면 INFO             |
| `LENGTH`            | 이력서 2쪽 초과(PDF 쪽수) 또는 4,000자 초과                           | INFO                                 |

`GET /document-versions/{id}/ats-check`로 조회하고, 회고 비교 대상(`review-context`)은 제출 버전의 결과를 포함합니다.

## 내보내기 상태

```
REQUESTED -> RENDERING -> VALIDATING -> READY | FAILED | EXPIRED
```

실패 결과는 내부 예외 대신 사용자 행동 가능한 오류 코드를 제공합니다. 동일 문서 버전과 템플릿 조합의 재시도는 가능하면 기존 성공 산출물을 재사용합니다.

## 구현

렌더러는 `packages/document-renderer`(순수 Kotlin + Apache POI, [ADR-0009](../architecture/adr/0009-document-rendering-and-export-storage.md))이며 `apps/worker`의 `document.export` Job이 실행합니다. `DocxRenderer`는 단일 열·제목 계층·본문 11pt로 쓰고, `ExportValidator`가 텍스트를 재추출해 모든 블록이 순서대로 있는지 검사합니다. `PDF`는 `PdfRenderer`(OpenPDF, Noto Sans KR 서브셋 임베딩)가, `MARKDOWN`/`JSON`도 같은 모듈이 만듭니다. 산출물은 당분간 PostgreSQL `export_files`에 저장하고 `GET /exports/{id}/file`로만 내려받습니다.
