# 화면 명세 (디자인)

기준 시안: `docs/source/ProofU_디자인_기획서_v1.0.docx` 그림 1.

## D01 대시보드

현재 데이터의 건강도와 지원 진행 상황을 요약하고 다음에 해야 할 일을 제안합니다. 상세 분석 화면이 아니라 상태 확인과 빠른 이동의 출발점입니다.

| 영역            | 표시 정보                                                    | 주요 동작           | 빈 상태             |
| --------------- | ------------------------------------------------------------ | ------------------- | ------------------- |
| KPI 카드 (4열)  | 전체 경력 기록, 검증된 Evidence, 진행 중인 지원, 근거 연결률 | 관련 목록으로 이동  | 0 값과 첫 등록 버튼 |
| 커리어 타임라인 | 기간, 역할, 프로젝트, 성과, Evidence 수                      | 필터, 상세 열기     | 샘플 없이 입력 안내 |
| 주요 기술       | 기술별 연결된 프로젝트 수, 자기평가 수준, 마지막 사용        | 기술 관리 이동      | 첫 기술 등록 유도   |
| 최근 Evidence   | 파일명, 유형, 날짜, 검증 상태                                | 미리보기, 연결 관리 | 업로드와 URL 추가   |

KPI 정의:

| 지표            | 정의                                 | 주의                            |
| --------------- | ------------------------------------ | ------------------------------- |
| 전체 경력 기록  | 공개 및 비공개 Career Entry 총합     | 삭제 항목 제외                  |
| 검증된 Evidence | 검증 상태가 verified인 Evidence 수   | 링크 만료는 별도 경고           |
| 진행 중인 지원  | 종료 상태가 아닌 Application 수      | withdrawn 제외                  |
| 근거 연결률     | 활성 Claim 중 Evidence가 연결된 비율 | 근거 없는 수치 문장은 별도 오류 |

- 타임라인 필터: 전체, 프로젝트, 근무 경력, 성과, 자격증.
- 카드 클릭 영역 전체가 링크이며 키보드 포커스가 명확해야 합니다.
- 지표 변화는 전 기간 대비 수치와 방향을 함께 표시하되 색상만으로 구분하지 않습니다.
- 행동이 필요한 항목은 최대 3개까지만 우선 노출합니다. 순서: 7일 내 마감 → 회고 대기 결과 → AI 요구사항 초안 승인 → 매칭 미실행(승인 요구사항 있음) → 미승인 문장이 남은 문서 → 근거 없는 주장 → 미검증 Evidence → 프로젝트 없는 경력 (`AttentionCode`).

## C01/C02 커리어

기본 보기는 타임라인이며 테이블 보기와 관계 보기를 선택할 수 있습니다. 각 항목은 기간, 역할, 요약, 연결된 성과, Evidence 수, 공개 범위를 표시합니다.

| 필드 그룹 | 필수 항목         | 보조 항목                  |
| --------- | ----------------- | -------------------------- |
| 기본 정보 | 유형, 제목, 기간  | 회사·조직, 위치, 공개 범위 |
| 역할      | 직책, 책임        | 팀 규모, 협업 대상         |
| 성과      | 행동, 결과        | 수치, 기준, 기간, 신뢰도   |
| 기술      | 기술명, 활용 수준 | 사용 기간, 버전            |
| 근거      | 연결 Evidence     | 관계 유형, 인용 범위       |

## E01/E02 Evidence

| 열          | 설명                         | 동작      |
| ----------- | ---------------------------- | --------- |
| 제목        | 사용자가 정한 Evidence 이름  | 상세 열기 |
| 유형        | 문서, 링크, 이미지, 텍스트   | 유형 필터 |
| 검증 상태   | 검증됨, 검토 필요, 만료      | 검증 상세 |
| 공개 범위   | 비공개, 선택 공개, 전체 공개 | 범위 변경 |
| 연결된 주장 | Claim 연결 개수              | 관계 보기 |
| 수정일      | 최근 변경 시각               | 정렬      |

상세: 상단에 제목, 유형, 검증 상태, 공개 범위, 원천 URL/파일 정보. 미리보기와 메타데이터를 나란히 배치(작은 화면은 세로). 연결된 경력과 Claim 목록, 관계 추가·해제. 민감한 내용은 AI 처리 전 명시적 동의. 링크 만료, 파일 손상, 권한 부족은 복구 행동과 함께 표시.

## J02 공고 매칭

공고 요구사항과 추천 경력 및 Evidence를 좌우로 대응시킵니다.

| 영역          | 내용                           | 상호작용                   |
| ------------- | ------------------------------ | -------------------------- |
| 공고 요약     | 회사, 직무, 경력 수준, 태그    | 원문 보기, 분석 다시 실행  |
| 요구사항 목록 | 필수·우대 분류, 원문 인용      | 항목 선택, 편집, 제외      |
| 추천 결과     | 경력, Evidence, 점수, 이유     | 채택, 제외, 대체 항목 보기 |
| 갭 분석       | 근거 부족, 최신성 부족, 미보유 | 경력 보완 또는 직접 입력   |

- 점수는 0~100 정수와 낮음/보통/높음 라벨을 함께 표시. 색상은 보조 수단.
- 추천 이유는 요구사항과 Evidence에서 일치한 핵심 구절을 각각 보여줍니다.
- 근거가 없거나 추론만 가능한 추천은 검토 필요 상태이며 자동 채택하지 않습니다.
- 정렬 기본값: 필수 요구사항 우선 → 신뢰도 내림차순.
- 사용자는 모든 추천을 선택, 제외, 대체할 수 있습니다. AI 분석이 갱신되어도 사용자의 채택 결과는 덮어쓰지 않고 차이를 비교합니다.

## R01 지원 문서 편집기

| 영역          | 너비             | 내용                                           |
| ------------- | ---------------- | ---------------------------------------------- |
| 문서 구조     | 240px            | 섹션 목록, 순서, 오류 상태                     |
| 편집 캔버스   | 가변, 최소 600px | 이력서·자기소개서 본문                         |
| Evidence 패널 | 320px            | 추천 근거, 연결 상태, 검색                     |
| 상단 도구     | 전체             | 저장, 미리보기, ATS 검사, 버전 기록, 문서 생성 |

근거 연결 흐름: 문장/Claim 선택 → 우측 패널에서 추천 Evidence 확인 → 연결 시 문장 하단에 출처 칩 → 근거 없는 수치·단정 문장은 경고 → 내보내기 전 사용자 최종 승인.

## R02 버전 기록

| 상태        | 동작                           | 표시                              |
| ----------- | ------------------------------ | --------------------------------- |
| 자동 저장   | 편집 후 짧은 지연 저장         | 저장 중, 저장됨, 오류             |
| 명명 버전   | 사용자가 버전 이름과 메모 저장 | 시각, 작성자, 공고, 템플릿        |
| 제출 스냅샷 | 지원 제출 시 불변 버전 생성    | 잠금 아이콘, 제출 시각            |
| 비교        | 두 버전 선택                   | 추가·삭제·변경을 문장 단위로 표시 |

ATS 검사는 파일 형식, 제목 구조, 표와 이미지 사용, 핵심 키워드 누락, 연락처 파싱 가능성을 확인합니다. 합격 가능성 점수로 표현하지 않습니다.

## A01/A02 지원 관리와 회고

[domain/application-lifecycle.md](../domain/application-lifecycle.md) 참고. 회고 화면은 확정 사실, 가설, 개선 행동을 분리하고, 비교 대상으로 공고 스냅샷, 제출 문서 버전, Evidence 연결률, ATS 검사 결과를 제공합니다. 면접 인계 전에는 대상 데이터와 목적을 확인하는 검토 화면을 제공하며 취소와 재전송 상태를 표시합니다.
